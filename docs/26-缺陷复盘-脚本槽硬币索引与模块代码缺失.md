## 2. 定位方法（给 AI 的检索路径）

### 2.1 从提示文案反查

```powershell
cd 'E:\辅助文件\Mod编辑器\编辑器正式稿\开发资料\src'
Select-String -Path web\app.js -Pattern '还没有代码'
```

命中的就是 `addSlotFromModule()`。看它上一行：

```js
const m = (S.modules || []).find((x) => x.id === mid);
const code = String((m && m.code) || '').trim();
```

→ 问题变成：「`S.modules` 里的项，`code` 从哪来？」

### 2.2 反查数据来源（关键一步）

```powershell
Select-String -Path web\app.js -Pattern 'S\.modules ='
```

输出 4 处：`loadModules()`、`loadSkillList()`、`loadPassiveList()`、`loadBuffList()`。

```powershell
Select-String -Path server\api.mjs -Pattern 'modules: listModules\(letheRoot\)'
```

输出 3 处（`:810` `/api/skills`、`:1088` `/api/passives`、`:1227` `/api/buffs`），**都没有计算 `code`**；
而 `/api/modules` 那段（`:994-1001` 附近）是唯一做了 `compileProgram(...).join('\n')` 的地方。

**结论**：同一份"模块列表"有两条形状；只有走 `/api/modules` 的入口带 `code`。
**通用规律**：只要看到「前端某处读 `x.<派生字段>` 得到 `undefined`」，先找这个字段在**所有**返回同族数据的接口里是否一致，而不是只盯报错那一行。

### 2.3 验证 B：抓请求体（最快的证据）

在页面里挂一层 fetch 记录（CDP 或临时脚本）：

```js
window.__reqs = [];
const of = window.fetch;
window.fetch = function (u, o) { return of(u, o).then(r => { window.__reqs.push([String(u), r.status, o && o.body ? String(o.body).slice(0, 200) : '']); return r; }); };
```

然后点「硬币 1」的 ×，读 `window.__reqs`：

```
["/api/script/slots", 200, "{\"where\":\"coin\",\"coin\":-1,\"texts\":[…]}"]
```

`coin` 是 `-1` ——而界面上点的是**硬币 1**。这就是铁证。
对照点「硬币 2」：`"coin":1`，删除生效。

### 2.4 验证 B 的服务端行为（不经过 UI）

```js
// 直接调接口：同一批文本，分别用 coin=0 与 coin=-1 写，再回读
await POST('/api/script/slots', { name, kind:'skill', id, where:'coin', coin: -1, texts });  // 200
await GET('/api/skill?...');                                                                  // 条数不变
await POST('/api/script/slots', { name, kind:'skill', id, where:'coin', coin: 0,  texts });  // 200
await GET('/api/skill?...');                                                                  // 条数 +1
```

本次实测：`coin:-1` → 3 次全丢；`coin:0` → 3 次全落盘。

### 2.5 看懂服务端为什么"静默"

`开发资料/src/lethe/scriptslot.mjs:120-125`：

```js
if (String(where) === 'coin') {
  const ci = Number(coin) || 0;              // -1 是 truthy，所以 ci = -1
  if (!Array.isArray(seg.coinList)) seg.coinList = [];
  const c = (seg.coinList[ci] = seg.coinList[ci] || {});   // 给数组挂了 "-1" 属性
  c.abilityScriptList = list.map(...);
}
```

`arr[-1] = {}` 在 JS 里合法，但**不是数组元素**；`JSON.stringify(arr)` 只序列化索引 0..length-1，所以这个属性写盘时凭空消失，接口却已返回成功。
**判据**：任何"写成功但读不到"的问题，先检查写入的 key 是不是"对象/数组上不存在的形状"（负数、`undefined`、`NaN`、带空格的名字）。

## 3. 修复（按顺序做，每步都能独立验证）

### 3.1 后端：让"模块列表"只有一个出口

在 `开发资料/src/server/api.mjs` 里加一个 helper（放在 `listModules` 的 import 之后即可）：

```js
// 派生字段（code）只在这里算，任何返回模块列表的接口都必须走它
function moduleRows(letheRoot) {
  return listModules(letheRoot).map((m) => {
    const rows = compileProgram(m.program);
    return { ...m, code: Array.isArray(rows) ? rows.join('\n') : String(rows || '') };
  });
}
```

把 4 个调用点统一替换：

```powershell
Select-String -Path server\api.mjs -Pattern 'listModules\(letheRoot\)'
# 期望 4 处：/api/modules 的内联 map、/api/skills:810、/api/passives:1088、/api/buffs:1227
```

- `/api/modules`：把内联的 `code: ...` 删掉，改为 `modules: moduleRows(letheRoot)`。
- 其余三处：`modules: moduleRows(letheRoot)`。

**注意**：`compileProgram()` 返回的是**行数组**（每行一段脚本），必须 `.join('\n')`；直接塞进字段会导致前端显示 `[]` 或 `[object Object]`（v0.9.18 踩过）。

**性能**：若模块数很多，给 `moduleRows` 加按 `mtime+size` 的缓存；先量测再优化（本次 200 条 < 5 ms）。

### 3.2 前端：不要用 `||` 给"编号"兜底

`开发资料/src/web/app.js:3399`：

```js
// 改前
coin: Number(coin) || -1,
// 改后
coin: where === 'coin' ? Number(coin) : -1,
```

同时把 `addSlotFromModule()` 里 push 的那句（`:3413`）保持 `zone === 'coin' ? Number(coin) : -1`（本来就是对的，别改坏）。

**通用规则**：`0`、`''`、`false` 都是**合法取值**，永远不要用 `||` / `&&` 做兜底；需要兜底就用 `??` 或显式 `Number.isFinite()`。

### 3.3 服务端：非法输入必须报错，不许静默

`开发资料/src/lethe/scriptslot.mjs` 的 coin 分支改成：

```js
if (String(where) === 'coin') {
  const ci = Number(coin);
  if (!Number.isInteger(ci) || ci < 0) throw new SafetyError('硬币序号无效：' + String(coin));
  if (!Array.isArray(seg.coinList) || ci >= seg.coinList.length) {
    throw new SafetyError('硬币序号超出范围（本技能 ' + (seg.coinList || []).length + ' 枚）：' + ci);
  }
  const c = (seg.coinList[ci] = seg.coinList[ci] || {});
  ...
}
```

`SafetyError` 会被路由层映射成 **400**（见 `src/server/http.mjs` 的 `sendError`），不会写盘。

**同时处理历史脏数据**：读取侧（`api.mjs` 的 `scriptSlots()`）过滤掉 `coin < 0` 或 `>= coinList.length` 的槽，并给它们打 `invalid: true`，让前端显示为"无效槽（建议删除）"，而不是让保存直接失败。

## 4. 为什么这两个 bug 会被漏掉（复盘）

1. **验收只覆盖了"写 API"而不是"用界面"**：v0.9.19 我用 `/api/script/slots` 直接写槽位，再数 DOM 里的块数，绕过了"拖入取 `code`"这条路径。
2. **新增派生字段只改了一个出口**：v0.9.18 给 `/api/modules` 加 `code` 时，没有回头检查"还有谁在返回模块列表"。
3. **`||` 兜底没有评审点**：这类写法不会报错，只会安静地把 0 变成 -1。
4. **服务端对"不存在的形状"过于宽容**：`arr[-1]` 不抛错，是语言特性，但产品上必须视为非法。

## 5. 防复发的硬规则（建议写进团队约定）

### 5.1 数据出口唯一

- 任何"同一实体的列表/详情"，只允许一个函数产出**同一种形状**；派生的展示字段（如 `code`、`hp65`、`rankLabel`）也在这个函数里算。
- 加字段时，用「按函数名 `listModules` 全局搜索」确认所有出口都改到。
  ```powershell
  Select-String -Path server\*.mjs -Pattern 'listModules\(' -Context 0,1
  ```

### 5.2 编号/索引必须有校验器

新增 `src/safety.mjs` 的一个工具（建议名 `toIndex`）：

```js
export function toIndex(value, { min = 0, max = Number.MAX_SAFE_INTEGER, field = '索引' } = {}) {
  const n = Number(value);
  if (!Number.isInteger(n)) throw new SafetyError(field + '必须是整数：' + String(value));
  if (n < min || n > max) throw new SafetyError(field + '超出范围（' + min + '~' + max + '）：' + n);
  return n;
}
```

约定：**前端、后端两侧**所有 `coin / index / slot / level / wave` 都走它；禁止 `Number(x) || 0/-1`。

### 5.3 提交前 Checklist（写进 PR 模板）

- [ ] 新增/修改接口字段时，是否同步了**所有**返回同族数据的接口？
- [ ] 有没有用 `||` 处理可能为 `0` 的值？（搜索 `|| -1`、`|| 0`、`Number(`）
- [ ] 服务端对非法输入是 400 还是静默 200？静默的在评审中必须解释。
- [ ] 是否新增了至少一条契约测试覆盖"写→读→删→读"？
- [ ] 是否用**真鼠标**做过一次 UI 回归（不是 `element.click()`）？
- [ ] 改完是否 `node --check` 了前端、`npm test` 全绿？

### 5.4 让"静默"变成"响亮"

- 前端 `api()` 已经会在 `!res.ok` 时抛错；再加一条：`res.ok` 但返回体 `ok === false` 也要 toast 出来（历史上出现过"接口 200、业务失败"被吞）。
- 服务端所有写接口统一走 `SafetyError` → 400，避免"200 但没写"。

### 5.5 CI / 构建门禁

- `build-server.mjs` 不校验语法；建议在 `npm run build:server` 前置 `node --check src/web/app.js`（已有工具链，零依赖即可做）。
- `npm test` 里包含契约测试后，任何"少算一个派生字段"都会在 CI 里红掉。

## 6. 同类风险清单（本次扫描结果，供顺手修）

在 `开发资料/src/web/app.js` 中，以下位置存在"0 被当空值"的风险，需逐个确认是否合法语义（多数是"数值输入 0 被允许"的场景，误改会造成新 bug，**只改索引/编号类**）：

- `:723` `Number(id) || 1`（罪人编号，1 起，无 0 语义 → 安全）
- `:937/:938/:947/:1049` `pct`/`rank`（0 是合法百分比 → 应改 `??`，但属 UI 显示，另开单）
- `:3368` `const idx = Number(s.index) || 0`（槽位 index，0 合法 → 建议 `toIndex(s.index, {min:0})`）
- `:3399` **本次修复点**
- `:5256/:5745/:6034` `Number(val) || 0`（积木数字块，0 合法 → 改 `??` 或 `Number.isFinite` 判断）

服务端：

- `scriptslot.mjs:121` `Number(coin) || 0` —— **本次一并修**。
- 其它 `Number(x) || N` 建议用 `grep`/`Select-String` 全量列出后按"是否索引"分类处理。
