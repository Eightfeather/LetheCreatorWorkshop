# 后续路线图（v0.9.20 交接版）

> **这份文件解决什么问题**：`docs/20`（工程体检）、`docs/21`（功能大纲）、`docs/23`（用户视角待办）三份各自成立，但互不引用、没有统一优先级。接手人要先读完三份才能自己拼出"先做什么"。这里把它们合成**一张带优先级、依赖、预估和验收口径的总表**。
>
> **怎么用**：先看 §1 的档位划分，再看 §2/§3/§4 里与你相关的行；每行的"验收口径"是可以照着验的，不是"感觉做完了"。
>
> **更新规则**：任一项状态变化（开始/完成/放弃）当天改本表，并在 §7 记一行；不要另起文件。

---

## 1. 现状与判断

- 版本：**v0.9.20**（2026-11-09）；`npm test` 42/42、`npm run smoke` 18/18。
- 已闭环：模块↔Modular 语法双向、技能/被动/Buff/人格四类编辑、镜牢六表、事务写盘（tmp→备份→原子替换→失败回滚）、LCW 数据目录、发布链（`tools/release.mjs` → GitHub Releases）。
- **未闭环的三处结构性断点**（本路线图的主线）：
  1. **模块编好之后没有"去向"**——模块能编译成脚本，但要人手动把它拖进某个技能/被动/Buff，没有引用关系表、没有孤儿体检。
  2. **编辑器看不到游戏**——改完只能"看起来对"，没有实机验证回路（不读 `BepInEx\LogOutput.log`）。
  3. **理解成本高**——3,937 条官方脚本效果库（`script-effects.json`）没接进界面，用户要自己猜"这个脚本干什么"。

> 一句话结论：**工程已合格，产品还没闭环**。1.0.0 的门槛不是"再多几个编辑器"，而是把上面三处接上。

### P0-1 模块引用同步

**问题**：模块存于 `<私服根>\LCW\projects\modules`，是全局的；技能/被动/Buff 只在"置入区"里存**脚本文本**。改了模块，用到它的地方**不会跟着变**；删了模块，引用处变成看不懂的裸脚本。

**做法**（建议）：
1. 后端在保存模块时，扫 `LCW/projects/{skills,passives,buffs}` 与各 Mod 的 `custom_limbus_data`，把 `canonicalCode(模块)` 作为键建**反向索引**：`模块 id → [{kind, mod, id, where, coin, index}]`。
2. 模块保存后，若索引非空且编译结果变了 → 弹窗列出引用点，让用户选"全部更新 / 只更新本次 / 不更新"。
3. 加一个只读的"引用体检"面板：孤儿模块（0 引用）、悬空引用（引用的模块已不存在）、编译失败的模块。

**验收口径**：
- 建模块 M → 拖进技能 S1 与被动 P1 → 改 M 的描述 → 保存 → 提示"2 处引用"→ 选"全部更新"→ 读回 S1/P1 的脚本文本均为新编译结果。
- 删除 M → 引用体检面板出现 2 条"悬空引用"，点跳转能定位到具体位置。
- `npm test` 增加至少 6 条断言覆盖上述路径。

### P0-2 实机验证回路

**问题**：所有"已验证"都是 CDP/DOM 层面的，没人证明游戏里真的跑对了。`23`#16/#17 记的正是这个。

**做法**：
1. 设置页加"实机验证"分区：显示 `LimbusCompany.exe` 路径、`BepInEx\LogOutput.log` 路径与最后修改时间。
2. 一键"启动游戏并盯日志"：拉起游戏 → tail `LogOutput.log` → 抓 `Exception`/`NullReference`/`Modular` 相关行 → 回到编辑器展示成"本次会话告警列表"。
3. 每个可写对象（人格/技能/被动/Buff）加一个 **"已验证"标记**（存在 `LCW/state.json`，记录时间与 Mod 版本），界面上给绿点；没标记的显示"未实机验证"。

**验收口径**：
- 故意造一个会抛异常的模块（例如 `skillreuse` 只写 1 参）→ 启动游戏 → 编辑器里能在 30 s 内看到对应告警行与来源文件。
- 正常保存一个技能并实机进战斗 → 该技能出现绿点，`state.json` 里有 `{verifiedAt, modMtime}`。

### P0-3 前端拆分

**问题**：`app.js` 已 40 万字符 / 7,000+ 行 / 350+ 函数；`innerHTML` 整页重建 27 处，靠 `refocus`、`pRestoreScroll`、`imeComposing`、`suppressClick` 一堆补丁维持。

**做法**（照 `20`§2.1 的 S2）：
1. `store.js`：唯一写入口 + 订阅；`S` 只读快照。
2. `views/*.js`：按页拆（home / mods / edit / skill / personality / md …），每页只读 store。
3. `patch.js`：局部 DOM 更新；`render()` 只负责挂载当前视图。
4. 事件：1 个 `click` 委托 + 1 个 `keydown` 路由表，其余局部监听并在卸载时移除。

**验收口径**：
- `app.js` 单文件 < 80 KB；`innerHTML =` 出现次数 < 8；`click` 全局监听 = 1、`keydown` = 1。
- `npm run smoke` 18/18 不变；人格页首开 < 400 ms；输入法连续输入 10 个汉字不丢字。

### P0-4 构建门禁

**问题**：`build-server.mjs` 不校验语法，坏代码会打包成功；版本号三处（`package.json`、`src/server/index.mjs`、`开发资料/host/*.csproj`）靠人工。

**做法**：`npm run build` 前置 `node --check` 所有 `src/**/*.mjs` 与 `node tools/verify-version.mjs`（三处一致校验）；`tools/release.mjs` 增加同样的前置。

**验收口径**：故意写坏一个 `.mjs` → `npm run build` 立即失败并指出文件与行号；把三处版本改成不一致 → 立即失败。

### P0-5 契约测试 + 未保存保护

**做法**：新增 `test/api-contract.test.mjs`（用 `tools/make-sandbox.mjs` 起沙箱，覆盖 20 条读写：人格 patch/save、技能 meta/code、被动/Buff、模块 program、script slots）；把人格/技能/被动/Buff 的切页也接上 `mbGuardDirty` 同款拦截。

**验收口径**：20 条契约测试全绿且能在 CI/本地一条命令跑；在四类编辑页改动后直接点底栏其它页，均弹"保存并离开 / 放弃 / 取消"。

## 3. P1 —— 1.0.0 之后第一波

| 编号 | 事项 | 来源 | 类型 | 依赖 | 预估 |
| --- | --- | --- | --- | --- | --- |
| P1-1 | 官方控件接入（`script-effects.json` 3,937 条） | `23`#24、`21` 第 116 行、我的评估 | 功能 | P0-1 的索引可复用 | 3 天 |
| P1-2 | 战斗编辑 / 敌人编辑（现为占位） | `23`#27、`21`§九 | 功能 | 数据可读已成 | 4 天 |
| P1-3 | 图片统一导入（立绘/技能图标/硬币/Buff/UI 切图） | `23`#20 | 功能 | 无 | 1 天 |
| P1-4 | 全局搜索与引用图 | 我的评估（三份文档都无） | 功能 | P0-1 | 2 天 |
| P1-5 | 新建 Mod 向导（空/模板/复制/派生） | 我的评估（三份文档都无） | 功能 | 无 | 1 天 |
| P1-6 | 诊断详情可复制 + 一键自检 | `23`#22、我的评估 | 体验 | 无 | 0.5 天 |

- **P1-1 官方控件**：按 `script-effects.json` 的 `effectSource` 分层（`curated` 优先），把"参数名 + 中文说明 + 示例"做成只读说明卡；允许整块导入但**只暴露已确证可改的参数**（`distinct>1` 的一律占位符）。**验收**：调色板里每个官方命令都能看到中文说明与示例；导入一个官方脚本后，编译结果与原文逐字一致。
- **P1-2 战斗/敌人**：先只读展示（读 `dumpedData` 的 `encounters`/`enemy`），再做"复制原版 → 改字段 → 写回 `custom_limbus_data`"。**验收**：能新建一个敌人并让它在镜牢表里被挑选到；实机进战斗不崩。
- **P1-3 图片导入**：统一入口（拖 PNG → 按类型落到 `custom_sprites/{profile,cg,skill,buffIcon}_<id>.png`）+ 尺寸校验 + 缩略预览。**验收**：五类图各导入 1 张，实机显示正确。
- **P1-4 全局搜索**：跨人格/技能/被动/Buff/模块/镜牢表，结果带"类型 + 所属 Mod + 跳转"。**验收**：搜一个中文词能同时列出 3 类以上结果，点击直达。
- **P1-5 新建 Mod 向导**：空 Mod / 从模板 / 复制已有 / 从原版派生；创建后自动建 `custom_limbus_data`、`custom_limbus_locale/EN`、`LCW` 记录。**验收**：新建的 Mod 在游戏里能被加载（日志出现 `Loading mod with name`）。
- **P1-6 诊断可复制**：诊断面板加"复制为 Markdown"；一键自检 = 环境（.NET/WebView2/私服路径）+ 数据（locale 冲突、id 溢出）+ 引用体检。

## 6. 1.0.0 的发布门槛（四道，缺一不可）

1. **P0-1 ~ P0-5 全部完成**，且 `npm test` ≥ 60 条、`npm run smoke` ≥ 18 条全绿。
2. **实机验证**：至少 3 个真实 Mod（含一个 >100 MB 的大 Mod）在游戏里加载、进战斗、无异常日志。
3. **数据契约冻结**：`docs/03-数据契约.md` 与实际写盘逐条核对一致；`docs/06` 的映射全部标为"已落地"或"明确不做"。
4. **交接完整**：桌面 zip 重新生成、`README-先读我.txt` 与 `docs/22` 的"首次搭建"命令逐条手敲验证通过。
