# 19 · 镜牢编辑（从清欣版 v0.8.18 移植）

> 版本：v0.9.0（2026-11-02）
> 定位：把清欣版（`E:\辅助文件\Mod编辑器\新建文件夹`，其自报 0.8.18/0.8.19）里的「镜牢相关内容」整套搬进本工程，并在底栏最右独立成一页 **镜牢编辑**；Mod 编辑里不再保留镜牢入口。

## 1. 移植了什么

| 层 | 文件 / 位置 | 说明 |

## 2. 六个类目（与清欣一致）

| kind | 名称 | 写进 Mod 的数据目录 | 本地化目录 | id 段 |
| --- | --- | --- | --- | --- |
| `cardpack` | 镜牢卡包 | `custom_limbus_data/mirrordungeon-theme-floor` | `mirrorDungeonThemeList`（EN/CN） | 9700 起 |
| `egogift` | 镜牢饰品 | `ego-gift` / `ego-gift-mirrordungeon` | `egoGiftList` | 9100 起 |
| `battle` | 战斗节点 | `battle-mirrordungeon` | `stageList` | 800000 起 |
| `enemy` | 敌人 | `abnormality-unit` | `enemyList` | 700000 起 |
| `mob` | 普通敌人 | `enemy` | `enemyList` | 710000 起 |
| `part` | 敌人部位 | `abnormality-part` | `enemyList` | 部位 id = 敌人 id × 100 + 序号 |

> 「敌人 / 普通敌人 / 敌人部位」是**三张不同的表**：敌人与普通敌人是两种实体（`abnormality-unit` 与 `enemy`），敌人部位是挂在敌人身上的子实体（`abnormality-part`，id 由敌人 id 派生）。这三者在清欣版里就是并列的三个向导项，本版保持并列。

## 3. 交互

- **草稿 → 落地**：新建只产生草稿（存在 `LCW/projects/{packs,gifts,battles,enemies,mobs,parts}/<Mod>/<id>.json`），点「落地到游戏文件」才写 Mod 目录；已落地的会出现「撤掉落地」（把文件搬进 `LCW/backups/md-remove/`，草稿保留）。
- **批量落地**：左栏底部「⇪ 批量落地」，把该类目下所有草稿落地。
- **克隆**：「载入现有{类目}」从游戏原版或已加载 Mod 里挑一条作为新草稿（`POST /api/md/clone`）。
- **挑选器**：字段右侧的「挑」按钮打开检索弹窗（技能/敌人/部位/饰品/卡包/战斗），选中即写入该字段。
- **双语**：名称/描述同时写 `EN` 与 `CN` 两个 locale 目录；`CN` 留空＝与 EN 相同。

## 4. 已知边界

- `id` 段与清欣一致，可能与已有的原版 id 冲突 → 新建时按「该类目最大 id + 1」生成，落前可用「载入现有」比对。
- 敌人/普通敌人/部位的**战斗引用**（战斗节点里引用敌人、敌人引用部位）目前靠手填 id，挑选器只填单体字段。
- 清欣还有「级联落地」（`landing.mjs`：人格 → 技能/被动 一次写全）与「官方脚本库」（`scriptdb.mjs`）**没有**搬过来——用户第 5 条要求把官方库改成模块编辑侧栏的「官方控件」大类，列为下一批。
- 本页是**移植**，后续若清欣重写镜牢模块，比对 `mdtables.mjs` 的 schema 差异即可。

## 5. 验证记录（v0.9.0）

- 接口（沙箱 `数据缓存/e2e-root`）：`/api/md/kinds` 返回六类；`/api/md/next?kind=cardpack&name=20901` → id 9700；`save` → `apply` 写出 3 个文件（数据 + EN + CN），内容为 `{list:[{id:9700,...}]}` 与 `{9700:{id,name,desc}}`；`remove-landed` 把文件搬走（数据文件消失）；`delete` 删草稿。
- UI（CDP 真鼠标，沙箱）：底栏 5 项 `home,mods,edit,import,md`；六张类目卡；进「镜牢卡包」→ 新建 → 输入名称/描述（`S.md.locale.name` 实时回写）→ 保存 → 落地（出现「撤掉落地」）→ 撤掉（按钮消失）→ 删草稿；挑选器弹窗能打开。
- UI（真实私服）：`敌人` 列出 `7.5-2桑丘` 的 1 条（id 107980、已落地），表单字段 `appearance/nameID/level/classType/attributeType/patternID/startActionSlotNum/maxActionSlotNum…` 正常渲染；`敌人部位` 列出 1 条（10798001）。

## 6. 本轮修掉的三个 bug

1. **`enterMdView()` 强制 `editKind='cardpack'`** → 进「镜牢编辑」直接落在卡包列表，六张类目卡永远看不到；改为「只有在已选类目时才载入列表」。
2. **`input` 监听器 TDZ 崩溃**：移植的 md 分支先用了 `t`，而 `const t = e.target` 声明在函数后半段 → 每次输入抛 `ReferenceError`，**所有**输入（人格名、描述、Buff 脚本…）全部失效；把 `const t` 提到监听器开头、删掉后面的重复声明。
3. **标题重复 id**：`loc.name || S.mdId` 与 `S.mdId` 拼在一起，未命名草稿显示成「97009700」；改为未命名时显示「未命名草稿」，并在输入名称时实时回显标题。
