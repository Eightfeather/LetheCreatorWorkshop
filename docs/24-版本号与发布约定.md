# 24 版本号与发布约定

> 生效日期：2026-11-09（用户定）。适用于 `The Lethe Workbench` 全部后续版本。

## 1. 冻结与 1.0.0 的门槛

- **`0.9.x` 在收到用户「人工通知」之前冻结**：不再新增功能版本，只允许修 bug 的补丁版本。
- 判定 `1.0.0` 的条件是**全流程走通**（不是"功能看起来齐了"）：
  1. 创建 Mod → 建人格 → 建/改技能 → 建/改被动 → 建/改 Buff → 模块积木编脚本 → 保存；
  2. 把成果装进游戏、**实机确认生效**（至少覆盖：人格可选中、技能可放、脚本触发一次）；
  3. 备份 / 回滚 / 禁用 / 删除 四条副作用路径各走一遍；
  4. 上述流程在**另一台机器**上（干净环境）复现一次。
- 四条都过，才发 `1.0.0`；在此之前一律 `0.9.x`。

## 2. 版本号历史与「重设」

- 2026-11-08 曾把 `0.9.12`–`0.9.37` 的全部改动**合并回 `0.9.11`** 作为基线，
  打 tag `v0.9.11-baseline`；之后版本号从 `0.9.12` 重新递增。
- 因此：`releases/` 里若同时出现两套同号目录，**以 `releases/<版本>/meta.json` 的 `gitHead` 为准**辨认真实产物。
- 相关 tag：`v0.8.7`、`v0.9.1-base`、`v0.9.11-baseline`、`v0.9.19`。

## 3. 递增规则

| 情况 | 递增 | 例子 |
| --- | --- | --- |
| 修 bug / 视觉微调 / 文案 | 补丁位 +1 | 0.9.19 → 0.9.20 |
| 新增一块功能（新向导页、新表） | 补丁位 +1（维持 0.9.x） | 0.9.20 → 0.9.21 |
| 架构级重写 / 数据格式不兼容 | 次版本位 +1 | 0.9.x → 0.10.0 |
| 四条实机验收全过 | 1.0.0 | — |

> 0.9.x 阶段**不规范语义化**（minor 位不动），只保证「补丁位单调递增」。

## 4. 一次发版的固定动作

```powershell
cd E:\辅助文件\Mod编辑器\编辑器正式稿\开发资料

# 1) 升版本（同步 package.json 与 src/server/index.mjs 的 VERSION）
node tools\bump.mjs 0.9.20 "一句话说明"

# 2) 语法自检（build-server 不校验语法！）
node --check src\web\app.js
node --check src\server\api.mjs

# 3) 构建
Stop-Process TheLetheWorkbench,TheLetheWorkbenchServer -ErrorAction SilentlyContinue
npm run build:server
npm run build:app

# 4) 回归
npm test                 # 单元 42 条
npm run smoke            # CDP 18 条（需要先有 exe）

# 5) 写记录：docs/04-验证记录.md 追加一节（改动点 + 实测数据 + 踩坑）
#    面向用户的变化写进 docs/CHANGELOG.md

# 6) 归档 + 提交 + 打 tag
node tools\switch-build.mjs save 0.9.20
git add -A
git commit -m "v0.9.20: <说明>"
git tag v0.9.20
git push origin main --tags

# 7) 发布（见 docs/15）
node tools\release.mjs 0.9.20
```

## 5. 入库规则

- **exe 不入库**（`.gitignore` 已排除 `*.exe` / `*.dll` / `*.exe.gz`），成品走 GitHub Releases。
- `releases/` 是**本机构建产物库**，不入库；只保留「还在支持的两个版本」（当前 `0.9.11`、`0.9.19`）。
- `node_modules/`、`build/`、`dist/`、`host/obj`、`config.json`、一次性脚本（`_*.cjs/_*.mjs`）不入库。
- 每次提交只做一件事（用户定规）：**一功能一提交**，出问题能 `git revert`，不必写反向补丁。

## 6. 发布渠道与命名

- **主渠道**：GitHub Releases（`tools/release.mjs`，需 `GITHUB_TOKEN`，仅本机环境变量）。
- **辅渠道**：桌面交接 zip（`TheLetheWorkbench-交接包-v<版本>-<日期>.zip`，含 exe + 源码 + docs + 沙箱），
  给没有 GitHub 访问权的人。
- Release 资产命名：`TheLetheWorkbench.exe`（主）、`TheLetheWorkbench-v<版本>-src.zip`（源码快照）。
- Release 说明模板：见 `docs/15-发布流程-GitHub-Releases.md`。

## 7. 版本自检（发版前必看）

```powershell
& 'E:\辅助文件\Mod编辑器\编辑器正式稿\TheLetheWorkbench.exe' version --json
# 期望：{"ok":true,"name":"the-lethe-workbench","version":"0.9.20","standalone":true,...}
```

版本号三处必须一致：`开发资料/package.json`、`src/server/index.mjs` 的 `VERSION`、界面底栏右侧 `vX.Y.Z`。
